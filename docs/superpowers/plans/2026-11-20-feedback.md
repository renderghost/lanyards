# Feedback to Our UserInput Board Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** People send bug reports and feedback, with screenshots, from
inside Lanyards to our board on userinput.app. Beside the form are links
to our Bluesky and our Signal.

**Architecture:**
- A piece of feedback is an `app.userinput.discussion` record that the
  app writes to the signed-in person's own repo. It points at our board,
  an `app.userinput.space` in @lanyards.app's repo, which we read live.
- Screenshots are re-encoded in the browser to fit 1 MB and uploaded as
  blobs first.
- The two extra OAuth scopes are asked for only from the feedback page,
  through a sign-in that requests them on top of today's.

**Tech Stack:**
- Vite, React 19, TanStack Router and Query, Tailwind v4 and Lingui;
- `@atcute` lexicons, pulled with `lex:pull` and typed with `lex:gen`;
- Canvas and `getDisplayMedia` for screenshots;
- Vitest with MSW and axe, and Playwright.

**Spec:** GitHub issue #134 (the findings and the owner's decisions).

## Global Constraints

- British English in all copy, through Lingui.
- CLAUDE.md's Form Standards:
  - visible labels;
  - `aria-invalid` and `aria-describedby` on errors;
  - focus on the first error;
  - no double submit;
  - a toast on success and on system errors;
  - never clear the form on error.
- 4-file component structure (5 with `.validation.ts` for forms).
- No margins, no inline styles; corners 1 px or 3 px.
- Scopes, verbatim:
  - `repo:app.userinput.discussion?action=create`
  - `blob:image/*`
- **The board's owner** is `did:plc:ua3d6biqepazbq6mw4ysotfo` (@lanyards.app). Read its newest `app.userinput.space`.
- **Bluesky:** `lanyards.app`. **Signal:** the username `renderghost.101`, with a Copy button.
- **The discussion record:**
  - `title` ≤ 300 graphemes, `body` ≤ 10,000 graphemes;
  - `tags` from the board's own tags (we send one, the chosen type);
  - images ≤ 4, each ≤ 1,000,000 bytes, PNG, JPEG, WebP or GIF, with `alt` ≤ 2,000.
- **URLs:** the board `https://userinput.app/s/<did>/<rkey>`, a post `https://userinput.app/d/<did>/<rkey>`.
- **The page says before sending** that the post and screenshots are public, and points to Signal for anything private, including security.
- **Technical details** are an opt-in tickbox, shown in full.
- **Signed-out visitors** see links only.
- **Initial JS** stays within the 200 KB budget: the page is a lazy route.

## Review Focus

1. **A large phone screenshot** (a 3–10 MB PNG): it is shrunk under 1 MB and attached, not rejected (Task 3: `fitUnder` unit tests; Task 5: the e2e uploads a 3 MB PNG).
2. **Permission missing or revoked by the time of sending:** the permission step appears and everything typed is kept (Task 4).
3. **The board edited between opening and sending:** the post references the board's current version, read at send time (Task 4).
4. **No board yet, or @lanyards.app's server unreachable:** the page says feedback isn't open yet and shows Bluesky and Signal, never a broken form (Tasks 2 and 5).
5. **Pasted text vs a pasted image:** pasting text into Details never adds an attachment; pasting an image anywhere in the form attaches it (Task 3).

### Task 3: Screenshots

**Files:**
- Create:
  - `web/src/features/feedback/images.ts`
  - `web/src/features/feedback/components/ScreenshotPicker/` (4 files plus a test)
- Test: `images.test.ts`, `ScreenshotPicker.test.tsx`

**Interfaces:**
- **Produces in `images.ts`:**
  - `MAX_IMAGE_BYTES = 1_000_000`; `MAX_SCREENSHOTS = 4`; `ACCEPTED_TYPES = ['image/png', 'image/jpeg', 'image/webp', 'image/gif']`
  - `fitUnder(maxBytes, encode: (scale: number, quality: number) => Promise<Blob>): Promise<Blob>`. Tries scale 1 at qualities 0.85, 0.7 and 0.55, then multiplies the scale by 0.75 at quality 0.7, down to 0.2; it throws `ImageTooLargeError` past that.
  - `prepareImage(file: Blob): Promise<Blob>`. Decodes, caps the longest side at 2,560 px, and encodes WebP, or JPEG where the browser can't encode WebP. Re-encoding always strips metadata.
  - `canCaptureScreen(): boolean`; `captureScreen(): Promise<Blob>` (`getDisplayMedia` with `preferCurrentTab`; one frame; stops the tracks)
- **Produces the component:** `<ScreenshotPicker value={Screenshot[]} onChange={(next) => void} error?={string} describedBy?={string} />`.
  - `Screenshot = { id: string; blob: Blob; previewUrl: string; alt: string }`
  - It has "Add screenshots" (file input, multiple, accept `ACCEPTED_TYPES`), "Capture this screen" (only when `canCaptureScreen()`), and per item a thumbnail, an "Alt text" input and a "Remove screenshot N" button.
  - It exports `useScreenshotPaste(onImages)`: attaches pasted image files from the form, and ignores text.

**Interfaces:**
- **Produces the details:** `techDetails({ page: string }): string`, lines `App: <version>`, `Browser: <name version>`, `Screen: <w>×<h>`, `Page: <path>`.
- **Produces the hook:** `useSendFeedback()` → a mutation of `FeedbackDraft = { type: string; title: string; details: string; screenshots: Screenshot[]; techDetails?: string }`. It resolves to `{ uri: string; url: string }`. In order, it:
  1. reads the board again with `fetchFeedbackBoard`;
  2. uploads each screenshot with `uploadBlob` (after `prepareImage`);
  3. calls `createRecord('app.userinput.discussion', { space: { uri, cid }, title, body, tags: [type], images, createdAt })`. The body is the details, plus `\n\n---\n` and the technical details in a fenced block when chosen.
- **Produces the component:** `<FeedbackForm board={FeedbackBoard} page={string} onSent={(result) => void} onNeedsPermission={() => void} />`.
  - **Type:** radios when the board has ≤ 5 tags, a select otherwise, required.
  - **Title:** required, ≤ 300 graphemes.
  - **Details:** ≤ 10,000 graphemes.
  - **Screenshots:** the picker.
  - **"Include technical details":** a tickbox, with the text shown in a `<pre>`.
  - **The public notice:** "Your feedback and screenshots are posted publicly from your account. For anything private, including security issues, message us on Signal."
  - **The button:** "Send feedback".
